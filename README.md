# 儿童产品风险召回

本项目服务于儿童用品风险与召回。认证、检测、批次流向、消费者反馈和分级召回需要协同。 系统应支持清晰的领域对象、事件记录和责任追溯，运行入口提供稳定的健康检查，便于本地联调和运维巡检。

运行 `python3 service.py --check` 可检查基础配置；执行 `python3 service.py --port 8000` 后访问 `/health` 可以确认服务身份。

## 领域模块（recall 包）

以儿童电话手表为场景，围绕"登记—分级开放—流向—处置—证据—追溯"闭环：

- `catalog` 登记册：型号、批次、固件先登记后引用；适龄结论与功能开关只追加事件；付费功能须登记付费规则；核心能力（基础通话、紧急求助、必要定位）不可设开关。
- `consent` 家长同意账本：同意与撤回只追加记录，可还原任一时刻的同意状态。
- `gating` 分级开放门禁：高风险能力按年龄与场景逐步开放，付费/高风险须家长同意；核心能力在任何停用、远程关闭下都保持可用。
- `inventory` 流向账本：生产、到店、跨店调拨、售出逐事件留痕并校验当前位置；离线盘点只核对差异，不改动归属，流向始终完整。
- `detection` 检测结论：结论变化作为新修订追加，旧结论保留；版本范围（型号+批次+固件）精确圈定受影响设备。
- `disposition` 处置：对指定版本分阶段停售、远程关闭高风险能力（核心能力禁止关闭）或召回，处置单引用触发它的结论修订。
- `notices` 通知：修订只追加，旧内容不可变，已售家庭可核对当时原文。
- `evidence` 证据：退款、换货、拒绝升级为终态证据；超期未处理可幂等推导留痕。
- `trace` 监管追溯：从一个序列号还原认证、销售和处置责任。
- `privacy` 最小可见：企业与门店的召回清单只含序列号、门店、家庭令牌与脱敏联系方式。

## 测试

`npm test`（或 `python3 -m unittest -v service_contract test_domain`）运行服务契约测试与领域规则测试。
